# OpenPrep governance

Repository owner AhmedU558 is the current project decision point. Git records Ahmed Umer/AhmedMA558 author names; no additional maintainer or legal ownership is inferred. Operational control does not settle copyright or trademark rights.

The maintainer triages issues, reviews code/content rights and medical disclosures, maintains checks/docs/notices, authorizes releases and coordinates private fixes. Contributors can propose focused issues/PRs, discuss alternatives and participate without automatically receiving merge/release authority.

Discuss routine decisions in a PR and record the rationale. Contested architecture, licensing, data and governance changes need an explicit maintainer decision after discussion. PRs require applicable passing checks, DCO/rights review, resolved conversations and maintainer approval. A solo maintainer needs an owner-approved documented review exception until another qualified reviewer is appointed; do not create an impossible approval rule. Branch protection is currently absent; this policy does not enable it.

Only the owner or an explicitly authorized release delegate can approve merge, tags, publication, releases, deployments or settings changes. Releases must check OPEN_SOURCE_READINESS; no policy can waive critical ownership/private-reporting/artifact-license blockers by declaring the project fully ready. This task creates no commit, push, release or deployment.

Succession requires explicit owner approval, a consenting named replacement, access/credential review and a recorded handoff of source, release and disclosure duties. This text does not invent maintainers or transfer copyrights.

Disputes start with respectful discussion and a written maintainer rationale. Conduct complaints require confidentiality and recusal when the decision-maker is involved; the parties must agree on an independent reviewer where needed. **The conduct reporting/enforcement process and private security channel remain pending configuration and maintainer approval before public release.** Follow CODE_OF_CONDUCT.md and SECURITY.md; never publish private complaints or vulnerability details in issues.
