# Dependency compliance review

2026-10-30. MIT remains active; this report does not activate AGPL or certify a distribution as legally compliant. No dependency was removed, replaced or upgraded in Phase 2. The npm lockfile remains the Phase 1 patch baseline (737 package paths). Distribution choices, license compatibility decisions and missing rights require owner/legal review.

## Complete review scope and evidence

Reviewed **every one of the 156 previously unresolved inventory entries**, plus 11 copyleft/compound entries with existing notices: 167 paths/artifacts total. All 167 downloaded npm tarballs matched the original lockfile integrity and package name/version; no package code or binary was installed, executed or extracted. The audit reads archive members and captures only notice text and bundled-version metadata. One interrupted/truncated cached download initially failed integrity; a fresh download passed the expected hash. It was never used as valid evidence or installed; no lockfile hash was relaxed.

63 artifacts contain captured notice files. Another 79 have captured upstream root license text: 64 at publisher-supplied gitHead commits, 15 at explicitly weaker version-tag candidates. **25 still lack sufficient captured license text.** A root grant is not proof of every file's license or exact binary/source correspondence. An intact tarball and a license identifier alone do not establish compliance. All targeted rows, including unresolved ones, are in [per-path review](audit/dependency-compliance-evidence.md) and [machine-readable receipts](audit/dependency-compliance-evidence.json). Deduplicated verbatim text lives in audit/dependency-evidence-texts/ with SHA-256 names and receipt links. Baseline inventory and captured notices remain intact; the new receipts supplement them.

Reproduce artifact verification/capture with `python scripts/dependency-evidence.py` (audit-only Python standard library; no application dependency). Publisher source references and retrieval URLs are recorded individually. Source-reference retrieval is a separate evidence step; the archive tool preserves those records on rerun but does not manufacture a missing source grant. Raw archives remain ignored under .release/dependency-evidence and are not part of a proposed release. No network service, production database, repository setting or package version was modified by this audit.

## Actual intended artifacts and inclusion evidence

Current intent is a public **source repository** and hosted Next.js application. No standalone executable release or application Dockerfile exists. docker-compose.yml provisions PostgreSQL/Mailpit for development, rather than building an OpenPrep container. Binary/container obligations below are prospective requirements, not claims that a reviewed artifact has been produced.

The local Windows Webpack build's server file traces include **sharp and @img/sharp native packages**. Thus native library obligations cannot be dismissed as dev-only. elkjs, lightningcss, axe-core, DOMPurify and caniuse-lite were not found by the narrow package-path query in these server traces; that does not prove absence from browser chunks, vendored code, Linux serverless traces, tooling caches or future containers. See [trace evidence](audit/phase2-distribution-trace.json). Lockfile dev flags describe dependency resolution, not what a particular image/bundle actually ships. Full browser/vendored/target-platform SBOM and binary provenance review remains outstanding.

## Approval boundary

Approve the intended artifact/platforms, evidence/notice bundle, source availability/relinking method, treatment of EPL combination and actual secondary grants, and any necessary exception or dependency change before release. No substitution/removal is proposed as an automatic shortcut. The technical gate can withhold a release; it cannot sign ownership approvals, reinterpret a grant, guarantee an upstream source/binary match or assign copyright.
