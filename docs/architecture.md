## Data model (summary)
`User` (role: LEARNER | EDITOR | ADMIN, preferences) · `Session`/`Account`/`Verification` (Better Auth) ·
`Exam` → `Subject`, `System`, `Topic` (taxonomy) ·
`Question` (type SINGLE | MULTIPLE, status DRAFT | REVIEW | PUBLISHED, difficulty 1–5, stemMd, explanationMd, keyPoints, references, source, license, isDemo, searchVector) → `Option` (text, isCorrect, explanationMd) ·
`TestSession` (mode TUTOR | TIMED, state, timeLimitSec, activeMs, startedAt, lastResumedAt, deadlineAt, negativeMark, examBlockId, version) → `SessionItem` (position, questionId, selectedOptionIds, flagged, struckOptionIds, highlights, state, timeMs, isCorrect, score) ·
`Response` (denormalized latest outcome per user+question, for pools and analytics) ·
`Bookmark`, `Note`, `Tag`, `Collection`, `Card` (SM-2), `CardReview`, `NotebookPage` (tree) ·
`StudyPlan` → `PlanTask` · `ContentReport` · `AuditLog` · `Asset`.

Indexes: `Question(examId, status)`, `Question(subjectId)`, `Question(systemId)`, GIN on `searchVector`, `SessionItem(sessionId, position)` unique, `Response(userId, questionId)` unique, `Card(userId, due)`, `AuditLog(entityType, entityId)`.

## Exam engine
- `machine.ts` is a pure function `transition(state, event) → state | error`, unit-tested exhaustively.
- **Timing is decided on the server.** `start`/`resume` set `lastResumedAt`; `pause` adds `now − lastResumedAt` to `activeMs`. For timed sessions, `remaining = timeLimit − activeMs − (now − lastResumedAt)`. The client countdown is only a display. Any answer arriving after the remaining time reaches 0 is rejected, and the next request auto-submits the session.
- **Submit is transactional and idempotent.** `UPDATE TestSession SET state='SUBMITTED', version=version+1 WHERE id=? AND userId=? AND state IN ('IN_PROGRESS','PAUSED') AND version=?` succeeds only once. Scoring and the `Response` upserts happen in the same transaction, so double-clicking or racing tabs cannot score twice.
- Each answer is saved to the server the moment it is chosen, so a refresh or crash loses nothing.

## Security model
- Every data query is scoped `where: { userId: session.user.id }`, done centrally in service functions (IDOR protection). Admin routes call `requireRole('EDITOR' | 'ADMIN')` on the server.
- Server actions and route handlers use Zod and scoped service boundaries. Prisma parameterizes queries; tagged SQL also covers search, analytics and exam row locking. See the security audit for review limits.
- Markdown is sanitized with DOMPurify before rendering. React escapes everything else. CSP headers are set in `next.config.ts`.
- Auth cookie behavior follows Better Auth and the configured HTTPS origin. Next.js server actions and Better Auth provide origin checks; the AI POST route has no additional explicit origin check and needs dedicated cross-origin verification.
- Better Auth rate-limits sign-in, sign-up and reset. Password reset tokens are single-use and expire.
- The logger redacts `password`, `token`, `cookie`, `authorization` and email addresses.
- No image-upload endpoint is implemented. Content imports can reference image URLs/paths; rights, origin restrictions and privacy require review.

## AI provider abstraction (optional)
`src/lib/ai.ts` exports `getProvider()`, which returns `null` when `AI_PROVIDER` is unset. The "Ask" panel renders only when a provider exists, so the core app never depends on AI. Built-in options are Ollama (local and free; it runs on your own hardware) and any OpenAI-compatible endpoint the user configures. Hosted inference usually costs money, and the UI says so.

## Costs (be explicit)
The software is free. **Hosting is not automatically free.** A public deployment needs a server or PaaS, a PostgreSQL database, a domain (optional) and SMTP delivery for password reset. Free tiers exist, but they change and are not guaranteed. Local use costs nothing.
