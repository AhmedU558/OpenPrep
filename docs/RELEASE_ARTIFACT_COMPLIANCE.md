# Release artifact compliance and reproducible preflight

2026-10-30. These are local candidate/input inventories, not release approvals. Nothing was published. MIT remains active.

## Inventories and boundaries

| Inventory | Observed material | Limits and obligations |
|---|---|---|
| SBOM_SOURCE.json | Nonignored public-safe repository files with SHA-256; all 737 lock paths as declared dependency references | References do not mean npm packages are bundled. Vendored CycloneDX schema 1.6 is separately recorded as actually included under Apache-2.0, with its retained upstream LICENSE and pinned commit. Do not impose binary source-offer duties on a package name merely mentioned in a lockfile. Actual repository files retain their notices and content gates. |
| SBOM_BROWSER.json | Actual .next/static assets and compiler-observed npm inputs | Compiled/minified modules may be partial. Next vendored dist/compiled components still need independent version/license mapping. Required recipient notices have not been placed/verified. |
| SBOM_HOSTED.json | Local .next/server files and in-workspace .nft trace closure, compiler inputs | Windows test build, not the deployed Linux/Vercel filesystem. Excludes private environment traces and reports omissions. Does not infer production compliance. |
| SBOM_NATIVE.json | Exact published native package archives and publisher-reported component union | Input inventory only; no final native server bundle supplied. All-platform inputs are not all shipped together. Library/source/relinking and static component identification remain open. |
| SBOM_CONTAINER.json | Explicit unbuilt candidate | No image digest, base OS, layer filesystem or platform evidence; empty inventory is blocked, not compliant. |

All five validate against captured official CycloneDX 1.6 schemas. File hashes identify local bytes. npm library hashes identify the published tarball, not a compiled chunk. Native component records explicitly identify publisher-reported platform unions, not independently proven local inclusion. Package declarations retain their compound expressions; no license alternative is silently selected. Native source URLs/hashes and 30 native file hashes are in `audit/phase3-native-evidence.json`. Per-platform selectors/versions and static import lists are retained there; dependencies absent from local output cannot be claimed absent from another platform build.

The source inventory excludes only private/ignored files and its self-referential SBOM, artifact-manifest, compliance-report and file-change sidecars. Those sidecars must be attached and hashed by the eventual outer release envelope. The tool does not build a distributable archive. Build input paths, compiler data, actual asset hashes and trace closure are in `audit/phase3-artifacts.json`. Compiler observation does not supply every third-party grant.

## Actual obligations by delivery method

Source-only repository delivery preserves grants/notices for code actually included, including generated/vendored code and educational content; registry dependency references alone do not convey those libraries. Downloading dependencies in a recipient's install is a distinct delivery boundary. Audit source exceptions and existing bundled assets rather than blanket-relicensing the repository.

Browser JavaScript/assets are conveyed to visitors even when the server is hosted privately. Include their required attribution/license/NOTICE material in an accessible, actually delivered notice resource; retain covered source offers where required. Plain private server execution does not itself convey every server library. Operators distributing server binaries, snapshots or containers must satisfy the obligations of components actually included. There is no AGPL network-use obligation from OpenPrep's active MIT license; a future valid AGPL transition requires a separate section 13/source review.

For MPL/EPL executable distribution, preserve covered notices and make the corresponding covered Source Code Form/modifications available under applicable terms, with the required recipient notice and source-location information. GPL/LGPL combined works need the selected version's corresponding-source and replacement/relinking arrangements, applicable installation material and permitted debugging modifications. A generic upstream URL is not proof a matching source offer works. Patent, attribution and NOTICE obligations for permissive/compound grants still apply. No generic secondary-license clause makes an entire dependency AGPL compatible. See PHASE_3_DEPENDENCY_RESOLUTION.md for boundaries and native exceptions.

A container review must inspect an actual immutable image, every distributed layer/base OS, OS packages, retained dev tools/caches, entrypoint/runtime dependencies, browser delivery and each architecture. Compose service images are not an OpenPrep image SBOM. Pinning a digest does not itself meet source/notice duties. No container image was built or cleared here.

## Reproduction

Use an isolated source checkout/copy without personal environment files. Preserve the lockfile. Tested runtime/tool versions are recorded in the validation evidence; Python 3.12 and the audit-only pre-existing jsonschema 4.25.1 were used. `jsonschema` is needed only for schema validation; it was not added to application dependencies. npm's own bundled Sigstore verifies provenance without an application dependency addition. GitHub CLI authentication/read access and network access to official npm/upstream sources are required for evidence retrieval. No fetched source or native binary is executed by audit scripts.

1. Run `npm ci`, then `npx prisma generate` with DATABASE_URL set to an unused local placeholder; generation does not connect. Never supply a production URL for testing/building.
2. To refresh evidence, run `python scripts/dependency-evidence.py`, `python scripts/audit-package-licenses.py`, then `npm run compliance:provenance`, `python scripts/audit-sharp-wrapper.py`, `python scripts/audit-native-dependencies.py`, and `python scripts/audit-covered-files.py`. Resolver output is intentionally refreshed before signed verification. Retain and review diffs; regenerated evidence is not approval. Read the recorded errors instead of replacing a missing license with metadata.
3. Set OPENPREP_COMPLIANCE_STATS=1 and NEXT_TELEMETRY_DISABLED=1; run `npm run build -- --webpack`. Stats must include cached modules and current source/config/lock input hashes. Use the intended target platform for a real release; a Windows validation build cannot stand in for a Linux image.
4. Run `npm run compliance:test`, `npm run compliance:sbom`, `npm run compliance:validate`, then `npm run release:preflight`. The SBOM command inventories bytes; it does not package/publish content. The preflight exits 1 while blocked and writes `docs/audit/phase3-compliance-report.json`. Do not ignore its exit code in any eventual publication job.
5. Run lint, typecheck, existing unit/integration/legacy/browser suites and actionlint. Integration/browser setup is permitted only in a newly created verified disposable local database, never an existing development/staging/learner DB. See PHASE_3_READINESS.md for this run's target and migrations.
6. Before a future release, assemble the actual approved artifact, source material and delivered notices; regenerate/validate inventories from it, independently review the composition gaps, and rerun preflight against those exact bytes. No release/publish action exists in these tools.

## Fail-closed decisions

`audit/phase3-release-policy.json` starts with empty distribution approvals, component permissions, source offers, artifact notice mappings and release-prerequisite approvals. No automatic approval migration occurs. Entries require an exact identity/scope, approved status, reviewer/evidence/date; duplicates conflict. Artifact notice records contain actual included path/SHA-256 records. For this implementation, corresponding-source bundles must exist, hash-match and be part of the inventoried delivered files, with an explicit reviewed source-offer record. Remote written offers are unsupported and remain blocked until recipient availability/retention and correspondence are verified and modeled.

Ownership authority, monitored private security reporting and conduct reporting each require an explicit reviewed release-prerequisite record; all remain absent here. The preflight checks required license-evidence presence and hashes, actual file hashes/file-set changes, lock/inventory consistency, compiler build input changes, SBOM hashes, delivered notices, source bundles, permissions and the existing content distribution gate for each scope. Missing data and exceptions fail nonzero. Native build/source/relinking review and incomplete vendor/target/container coverage remain explicit blockers. Source-declared external packages are recorded but are not automatically treated as conveyed binary components. The content gate still withholds all 58 rights-unapproved repository content paths; test-only attestations never populate release approvals.

The automated checks support evidence review; they do not validate a legal signer's authority, prove a source bundle reconstructs every binary, establish all minified/static component boundaries, or make raw repository files inaccessible to their owner. Human-reviewed records are operational attestations. No final compliance claim may rest solely on empty coverage errors or a package metadata license string.

CI now runs the standard-library compliance fixture tests. Local actionlint passes. Hosted CI, CodeQL and dependency-review execution remain untested because changes were not pushed; the release blocker check is an explicit preflight command, not a falsely green hosted release check. Publication/settings changes require separate authorization.

The merge preparation retains raw compliance evidence with `.gitattributes` binary/text-normalization exclusions so captured SHA-256 values survive checkout. Source/build inventories still describe local working-tree bytes; regenerate on the actual target checkout and assembled artifact. Git-triggered Vercel deployments are held in vercel.json pending separate release/migration approval.
