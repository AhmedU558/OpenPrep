# OpenPrep application release — 5 November 2026

This release adds the approved study dashboard design, descriptive practice-progress cards, difficulty selection, web-app metadata, practice reset/event history, immutable question revisions and review-aware delivery.

Practice resets retain historical attempts and apply event-sequence watermarks to future practice pools. Delivered revisions remain pinned for scoring and explanations. Existing unversioned content referenced by attempts or notebook clips cannot be rewritten in place. Candidate imports are create-only, keep new content withheld, and the import CLI explicitly targets a validated disposable database.

## Production behavior

The user selected the full update with existing questions withheld pending review. Production previously contained 1,028 stored questions: 1,017 published and 11 in review, with only the three original migrations. The additive rights migration defaults existing content to UNVERIFIED with delivery/export disabled. Neither a deployment authorization nor a license label is converted into rights or medical approval.

The release includes the rights migration already merged in main and four additional migrations for practice provenance and revision binding. No question import, seed, reset, approval fabrication or destructive migration is part of deployment. Unpublished question candidates, pilots, Step 3 batches and unfinished audit material remain outside this branch. Existing pending governance and content-review requirements remain recorded in the repository; this release does not certify their completion.

Node is pinned to 24 to match production. Build workers are capped at two for constrained machines. A scoped development-dependency override patches minimatch versions affected by [GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249); runtime dependency versions are retained.

## Validation and deployment

Validation results, the PR, merge commit, migration outcome and deployment identifier are recorded in the release handoff after checks complete. Tests use a newly created loopback PostgreSQL database containing synthetic fixtures only. Production inspection is limited to approved schema/migration metadata and aggregate counts; learner rows are not read for verification.
