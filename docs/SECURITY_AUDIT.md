## Boundary review

- Auth/session configuration: Better Auth password sessions, server-read role and input:false role field, reset expiry and revocation. No OAuth provider secrets/config were found. Signup does not require email verification. These are observed settings, not independent verification of the auth dependency internals.
- Authorization: actions call requireUser/requireRole, admin services check actor roles and learners use scoped services. Exam timing/scoring/transactions and late-answer behavior have existing tests. No bypass was demonstrated in this source review; this is not an exhaustive authorization proof.
- Injection/imports: Zod schemas, tagged/parameterized SQL and role-checked validated bulk imports are existing controls. Raw table truncation is confined to disposable tests. No uploaded binary handler or magic-byte validation was found; prior documentation incorrectly claimed one.
- XSS/CSRF: DOMPurify allowlists sanitize Markdown, highlights must match the base text after removing mark tags, and AI output is plain text. Next server actions/Better Auth provide origin protections; the AI POST route has no additional explicit origin check, so cross-origin behavior requires dedicated runtime verification. No universal CSRF claim is made.
- External AI: provider URLs/keys are operator-configured; user prompts and question context leave the instance when a hosted service is selected. Review provider retention, consent and prompt-injection limits before enabling. No AI provider call was made.
- Exports/deletion: user export selects user-owned data rather than auth secrets; CSV formula neutralization has tests. Privacy policy must address retained infrastructure backups and external providers. No complete live privacy/compliance assessment was performed.

## Credential/history evidence

Offline script scans every blob reachable from local refs: five commits, 225 unique blobs. It additionally scans current tracked and non-ignored new files without reading .env or connecting to a database. Patterns cover private-key headers, common provider/cloud/GitHub tokens, non-local credential URLs and long literal secret assignments. Reports contain **only path, commit and pattern label**, never matched values. No history matches were found. Current matches are synthetic CI/unit placeholder auth secrets and a reserved example-domain database URL in the isolation test; they are test values, not discovered credentials. Retain those findings for auditability rather than suppressing them.

No secret requiring rotation was established by this heuristic scan. No history cleanup is indicated by its results alone. Coverage excludes remote-only/unreachable objects, GitHub artifacts, private deployments, ignored files and secret formats outside the pattern set. If a real exposure is later confirmed, rotate/revoke immediately and assess history/artifact cleanup with the owner; do not infer deletion from HEAD makes it safe.

Ignore rules preserve .env.example and migrations while excluding .env*, dependencies/generated builds, reports/traces, logs, keys/cert stores, dumps/local database files, uploads, assistant state and deployment scratch. Tracked-file review did not identify a private-key file or real production credential. Public deployment URLs are intentionally public configuration, not credentials.

## Privacy and fixture review

Question vignettes declare synthetic AI authorship. Test accounts are generated with test.localhost addresses and throwaway passwords; CI credentials are disposable service fixtures. No production user record, student note, clinical record, private bank snapshot or live account data was exported for these deliverables. Per-item provenance contains declarations, hashes and public reference links, not learner data. Historical Git author metadata is already part of repository history; this task does not reproduce personal addresses or rewrite it. Third-party notice files preserve upstream author notices as legally supplied.

Existing content reports contain item IDs, timestamps and quality metadata; ignore rules exclude machine-specific preservation snapshots/hashes. Generated notice inventories do not inspect private packages outside the lockfile. Screenshots/traces remain ignored and are not auto-uploaded by CI. Supporting rights documents must be redacted for public evidence. User account retention, backups, incident handling and any jurisdiction-specific privacy obligations still require operator/legal review.

## Validation and limits

Exact final command results are recorded in [readiness](OPEN_SOURCE_READINESS.md). Fresh npm installation/client generation/schema validation, unit/legacy checks, workflow validation and advisory evidence are separate from runtime regressions. A new volume-free loopback PostgreSQL container is used for destructive test setup; the original app URL is replaced with an unused loopback port during checks. No production or existing study database is a test target. No hosted CodeQL scan, production smoke/load testing, clinical validation, whole-artifact license certification or forensic secret scan is claimed.
